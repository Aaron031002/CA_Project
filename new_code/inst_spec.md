# New CBI Inst. SPEC

> This document is aligned to the actual parser behavior in
> `Core/MainCtrl/Decoder/*` as of the current `new_code` tree. An earlier
> revision of this doc also covered a `RPC` instruction family (MoE
> expert-dispatch / TP fan-out over the NoC) — that entire subsystem has
> since been **physically deleted** from `MainCtrl`/`Decoder` (see
> [curr_arch.md §4.4](curr_arch.md)), so `RPC` is not a valid opcode here.
>
> `MainCtrl` (`Core/MainCtrl/MainCtrl.cpp`, `run()`) reads one instruction
> per line from `<inst_dir>/core_<i>_insts.txt`, strips a comment (`#` at the
> start of the line or after whitespace) and surrounding whitespace (incl. a
> CRLF `\r`), skips lines that are then empty, and hands each remaining line
> to `Decoder::decode(line)`
> (`Core/MainCtrl/Decoder/Decoder.cpp`). The first token (opcode) selects the
> sub-decoder:
>
> | opcode | sub-decoder |
> |---|---|
> | `Array` / `ARRAY` | `ArrayDec` |
> | `Vector` / `VECTOR` | `VectorDec` |
> | `DMA` | `DMADec` |
> | `TMU` | `TMUDec` |
> | `TCore` / `TCORE` | inline in `Decoder::decode` → `TCoreInst_t` |
>
> **Every line must decode exactly.** An unknown opcode, unit or mode
> (e.g. `Vectr`, `Vector RELUU`, `DMA DRAM reed`, `Array NORMLA`), a missing or
> non-numeric required field, or a leftover token the format doesn't allow
> makes the decoder throw `DecodeError`
> (`Core/MainCtrl/Decoder/DecodeError.h`), and `MainCtrl` stops the
> simulation before it starts:
>
> ```
> Fatal: MainCtrl/DECODE: core <i>, <inst_dir>/core_<i>_insts.txt:<line>: <reason>
>     > <the offending line>
> ```
>
> (Earlier versions printed a warning and skipped the line, or silently fell
> back to a default mode, so a typo ran as a different instruction.)
> Optional fields are still optional; the grammar below marks them with
> `[...]`. Instruction streams are generated by your own script (see
> [README.md §3](README.md) and USER_GUIDE.md §13).

## ArrayUnit

```
Array <mode> <layer_name> index  <row_start> <row_end> <col_start> <col_end>
      [stride <row_width>] <x_id> <out_id> <x_reserved>
      [kv_head_num] [q_seq_s k_seq_s_real win_size]   -- QK only
      [has_sink] [q_head_num]                          -- SV only
      [df WS|OS] [wsrc cache <w_id> <w_reserved>]

Array <mode> <layer_name> tensor <batch> <seq_start> <seq_end>
      <head_start> <head_end> [stride <row_width>] <x_id> <out_id> <x_reserved>
      [kv_head_num] [q_seq_s k_seq_s_real win_size]   -- QK only
      [has_sink] [q_head_num]                          -- SV only
      [df WS|OS] [wsrc cache <w_id> <w_reserved>]
```

#### mode
string, selects the operation: `NORMAL`, `DOT_PRODUCT`, `QK`, `SV`.
- The decoder accepts the opcode `Array` or `ARRAY`.
- A mode string not in this list fails to decode (`DecodeError`: the simulation stops with a fatal error, see the note at the top).

#### layer_name
string, the file name of the layer to compute with (used as the file path/name for the DRAM read). For `QK` give the K file, for `SV` the V file.

#### index_mode
`index` parses flat row/col coordinates; `tensor` parses batch/seq/head coordinates; any other string fails to decode (`DecodeError`).

- **index mode**: `row_start row_end col_start col_end`
- **tensor mode** (mostly used by `QK`/`SV`): `batch seq_start seq_end head_start head_end`, converted to:
  - `row_start = batch * MAX_SEQ_LEN + seq_start`
  - `row_end   = batch * MAX_SEQ_LEN + seq_end`
  - `col_start = head_start * HEAD_DIM`
  - `col_end   = head_end   * HEAD_DIM`

What `row`/`col` mean: row usually corresponds to `batch * max_seq_len`, col to `head_num * head_dim` (`HEAD_DIM`/`MAX_SEQ_LEN` are defined in `dram_params.h`).

#### stride (optional, directly after the coordinate block)
```
stride <row_width>
```
Overrides the file's actual row width (`row_stride` in `DRAMAddr_t`). Use it when `col_end` is smaller than the file's real row width (for example a TP shard that reads only some columns of a weight file, as in `Array NORMAL .../gate_weight.bin index 0 2880 0 1440 stride 2880 9000 9001 0`: the file is 2880 wide, and this instruction takes only the first 1440 columns). If omitted, `col_end` is used as the row width.

#### x_id / out_id / x_reserved
- `x_id` (uint64_t): the cache data id of the input activation.
- `out_id` (uint64_t): the cache data id the result is stored under.
- `x_reserved` (bool 0/1): `1` truncates (removes) the input from the cache after it has been read.

#### kv_head_num (optional, default `-1`)
GQA parameter; only has an effect in `QK`/`SV` mode.
- `-1`: standard MHA, K/V have as many heads as Q.
- `>0`: GQA mode. K/V use `kv_head_num` heads, Q uses `q_head_num = row / HEAD_DIM` heads, `group_size = q_head_num / kv_head_num`. In DRAM, K/V have only `kv_head_num * HEAD_DIM` elements along col: `K[t][kh][d] = weight[t * kv_head_num * HEAD_DIM + kh * HEAD_DIM + d]`.

> Parsing detail: the decoder always tries to read an int as `kv_head_num` (if that fails it keeps `-1` and clears the failbit). So `NORMAL`/`DOT_PRODUCT`, which have no such field, still parse correctly: when the next token is a `df`/`wsrc` keyword, the read fails and `-1` is kept.

#### QK-only optional parameters: causal mask
```
[q_seq_s] [k_seq_s_real] [win_size]
```
After `kv_head_num`. The decoder reads `q_seq_s` first, and only if it is `>= 0` also reads `k_seq_s_real win_size`; otherwise all three stay `-1` (no causal mask / sliding window).

#### SV-only optional parameters
After `kv_head_num`:
```
[has_sink] [q_head_num]
```
| Parameter | Type | Default | Meaning |
|------|------|------|------|
| `has_sink` | int (0/1) | `0` | Whether score column 0 is an attention-sink token |
| `q_head_num` | int | `-1` | Total number of Q heads for multi-token GQA; only takes effect when a value `> 0` is read, otherwise treated as not given |

#### df (optional)
```
df WS|OS
```
Overrides the systolic array's dataflow: `WS` = weight-stationary, `OS` = output-stationary. If omitted it is `AUTO`, chosen by mode (`NORMAL`/`DOT_PRODUCT` → weight-stationary, `QK`/`SV` → output-stationary; see `ArrayInst_t::resolved_dataflow()`).

#### wsrc (optional, must come after `df`)
```
wsrc cache <w_id> <w_reserved>
```
Takes the weight tile from the shared cache instead of DRAM (`w_id` = cache data id, `w_reserved` = 0/1: truncate it after reading). If omitted, `weight_src = DRAM` (the DRAM location given by `layer_name` and the row/col fields above).

## VectorUnit

```
Vector <mode> <dim> <x_id> <w_id> <out_id> <x_reserved> <w_reserved> [all] [out_id2]
```

**ROPE uses a different format (no weight):**
```
Vector ROPE <head_dim> <token_pos> <x_id> <out_id> <x_reserved> [theta]
```

#### mode
string, selects the operation:
`ADD`, `SUB`, `MUL` (aliases `mul`/`mult`), `RECIP`, `INV_SQRT`, `RELU`, `SIG` (sigmoid), `SILU`, `SWIGLU`,
`RMS` (alias `rmsnorm`), `SOFTMAX` (alias `softmax`), `ROPE`, `ADD_REDUCE`, `DOT_PRODUCT`, `TOP_K`,
`DIV_CONSTANT`, `BIAS_ADD`, `SPARSE_GATE`, `QUANTIZE_DEQUANT_Q8_0`, `REDUCE_MAX_ABS`,
`QUANTIZE_DEQUANT_Q8_0_EXT_SCALE`, `QUANTIZE_DEQUANT_Q8_0_BOUNDARY_FIX`.

- The decoder accepts the opcode `Vector` or `VECTOR`.
- A mode string not in this list fails to decode (`DecodeError`: the simulation stops with a fatal error, see the note at the top).
- All 6 fields of the general format (`dim` to `w_reserved`) are required; put `0` in `w_id`/`w_reserved` when they are not used.

#### Common fields
- `dim` (int): the axis/length to operate on; its meaning depends on the mode (see below).
- `x_id` (uint64_t): the cache data id of the input.
- `w_id` (uint64_t): the cache data id of the weight (unused by some modes, or given another meaning, see below).
- `out_id` (uint64_t): the cache data id of the output.
- `x_reserved` / `w_reserved` (bool 0/1): whether to truncate the corresponding cache entry after reading it.
- `all` (optional bool, default 0): only meaningful for `ADD_REDUCE`/`DOT_PRODUCT`; `0` = reduce along the `dim` axis, `1` = reduce over all elements.
- `out_id2` (optional uint64_t, default 0): this field position is used only by `TOP_K` and `SPARSE_GATE` (see below).

> **Which modes actually fetch a weight from the cache** (`needs_weight` in `VectorUnit.cpp`):
> `ADD`, `SUB`, `MUL`, `SWIGLU`, `RMS`, `BIAS_ADD`, `DOT_PRODUCT`, `SPARSE_GATE`,
> `QUANTIZE_DEQUANT_Q8_0_EXT_SCALE`, `QUANTIZE_DEQUANT_Q8_0_BOUNDARY_FIX`, and
> `SOFTMAX` only when `w_id > 0` or `w_reserved` is true. The other modes (`RECIP`,
> `INV_SQRT`, `RELU`, `SIG`, `SILU`, `ADD_REDUCE`, `TOP_K`, `DIV_CONSTANT`,
> `REDUCE_MAX_ABS`, `QUANTIZE_DEQUANT_Q8_0`, `IDLE`, `ROPE`) never fetch a
> weight; for them the `w_id`/`w_reserved` fields, if not empty, may be given
> another meaning (see `TOP_K`/`SPARSE_GATE`) instead of a cache data id.

#### SOFTMAX with an attention sink
Ordinary router softmax: `w_id=0` and `w_reserved=0` (no weight fetch; the same as the old softmax without a sink).
To add an attention sink, set `w_id` to the cache data id of the sink tensor (one scalar per softmax row, e.g. one per Q head), or set `w_reserved` to `1`; the sink value is then included in the softmax denominator.

#### TOP_K
```
Vector TOP_K <k> <x_id> <n_experts> <out_id> <x_reserved> 0 [all] <out_id2>
```
- `dim` = `k` (how many top values to take).
- **Here the `w_id` field means `n_experts` (an integer, not a cache data id)**:
  - `n_experts = 0` (legacy): a global top-k over the whole input; outputs only the sorted indices (`execute_top_k`).
  - `n_experts > 0`: the input is treated as rows of `[chunk, n_experts]`; top-k is taken per row, and the selected logits are renormalised into weights with a softmax (`execute_top_k_dual`, the MoE-router use).
  - `TOP_K` is not in the `needs_weight` list, so this integer never causes a cache fetch.
- Produces two `Data_t` outputs:
  - `out_id`: the top-k **indices** (sorted from largest to smallest value, integers stored as float; in per-row mode they are then re-sorted by expert index, ascending).
  - `out_id2`: the top-k **values** (the softmax-renormalised weights when `n_experts>0`; in legacy mode (`n_experts=0`) only the indices are meaningful, and the second output is written but not meant to be used).
- If `out_id2` is omitted or `0`, the second output is still written to the cache (as id 0); give it explicitly.

#### DIV_CONSTANT / RECIP / INV_SQRT / RELU / SIG / SILU
Single-input element-wise operations; `dim` = the number of elements processed; `w_id` is not used.

#### SWIGLU
`swiglu_oai` (the MoE activation of gpt-oss-20b, not a plain `silu(gate)*up`): `x_id` = gate, `w_id` = up. The gate is clamped only from above, up is clamped on both sides and gets a `+1` offset, and the sigmoid slope is `alpha=1.702` (see `VectorOp::execute_swiglu`). The inputs `x`/`w` have `dim` elements each; the output has `dim` elements.

#### BIAS_ADD
Broadcast bias addition: adds the bias of shape `[feature_dim]` (`w_id`) to every row of the input of shape `[..., feature_dim]` (`x_id`).
- `dim` = `feature_dim` (the bias length, i.e. the size of the input's last dimension); the input's total element count must be a multiple of `feature_dim`.
- The output has exactly the input's shape: `output[r*feature_dim+d] = input[r*feature_dim+d] + bias[d]`.
- `all` and `out_id2` are not used.

Example (adding the bias after a Q/K/V projection, `feature_dim=4096`):
```
Vector BIAS_ADD 4096 <proj_out_id> <bias_id> <result_id> 1 1
```

#### SPARSE_GATE
Expands the sparse routing produced by `TOP_K` (in `n_experts>0` mode: indices + renormalised weights) into a dense `[chunk, n_experts]` gate tensor: `gate[t,e] = renorm_weight` if `e` is among token `t`'s top-k, otherwise `0`.
- `x_id` = the indices output of TOP_K (`out_id`); `w_id` = the values output of TOP_K (`out_id2`).
- `dim` = `n_experts` (the row width of the output gate).
- **Here the `out_id2` field means `top_k`** (how many experts each token selected; it must equal the `dim` of the `TOP_K` instruction that produced `x_id`/`w_id`).
- Output shape: `[chunk, n_experts]`, where `chunk = len(x_id) / top_k`.

#### The QUANTIZE_DEQUANT_Q8_0 family
Q8_0 (blocks of 32 elements, symmetric int8 quantisation followed by dequantisation back to float, used to model quantisation error):
- `QUANTIZE_DEQUANT_Q8_0 <dim> <x_id> <w_id=unused> <out_id> ...`: standard per-block (32 elements) quantise/dequantise of the first `dim` elements of `x_id` (padded with 0 if shorter, extra elements ignored). Does not fetch a weight.
- `REDUCE_MAX_ABS <dim> <x_id> ...`: the maximum absolute value of the first `dim` elements of `x_id`, output as a single scalar (for `EXT_SCALE`/`BOUNDARY_FIX`). Same latency as one `ADD_REDUCE`.
- `QUANTIZE_DEQUANT_Q8_0_EXT_SCALE <dim> <x_id> <w_id> <out_id> ...`: `w_id` = a scalar tensor (`ext_scale_vec[0]`, usually the `REDUCE_MAX_ABS` result of another shard); all 32-element blocks share this one external scale instead of each using its own block maximum. Used to align quantisation scales across TP shards.
- `QUANTIZE_DEQUANT_Q8_0_BOUNDARY_FIX <dim> <x_id> <w_id> <out_id> ...` (`dim` must be a multiple of 32): standard per-block quantisation, except that for the **last block** the max_abs is first combined (max) with `w_id` (the external scale) before the quantisation scale is chosen. Used to fix the error of the block that straddles a shard boundary when TP-N splits `FFN_DIM` at a point that is not a multiple of 32 (e.g. `shard_dim=720` padded to `736`).

#### ROPE
Rotary Position Embedding. The VectorUnit computes cos/sin itself from `token_pos`/`head_dim`; **no weight data is needed** and no weight cache request is sent.

Format:
```
Vector ROPE <head_dim> <token_pos> <x_id> <out_id> <x_reserved> [theta]
```
| Parameter | Type | Meaning |
|------|------|------|
| `head_dim` | int | Embedding size of one head (must be even) |
| `token_pos` | int | Position of the token in the sequence (0-based) |
| `x_id` | uint64_t | Cache id of the input (shape `[head_dim]`) |
| `out_id` | uint64_t | Cache id of the output (same shape as the input) |
| `x_reserved` | bool | `1` truncates the input after it has been read |
| `theta` | float | Optional rotation base; default `10000.0` |

Computation (pair index `k = 0 … head_dim/2 - 1`):

$$\theta_k = \frac{token\_pos}{theta^{2k / head\_dim}}$$

$$out[2k]   = x[2k] \cos\theta_k - x[2k+1] \sin\theta_k$$

$$out[2k+1] = x[2k] \sin\theta_k + x[2k+1] \cos\theta_k$$

Example (head_dim=128, token at position 5):
```
Vector ROPE 128 5 <q_id> <q_rope_id> 0
```

## DMA

```
DMA NoC send  <packet_id> <data_id> <dest_id_0> [<dest_id_1> ...] [truncate]
DMA NoC recv  <packet_id> <data_id> <size_0> [<size_1> ...]

DMA DRAM read  <file_name> index  <row_start> <row_end> <col_start> <col_end> <data_id> [pad <n>]
DMA DRAM write <file_name> index  <row_start> <row_end> <col_start> <col_end> <data_id> <data_reserved> [pad <n>]
DMA DRAM read  <file_name> tensor <batch> <seq_start> <seq_end> <head_start> <head_end> <data_id> [pad <n>]
DMA DRAM write <file_name> tensor <batch> <seq_start> <seq_end> <head_start> <head_end> <data_id> <data_reserved> [pad <n>]

DMA Cache copy <src_data_id> <dst_data_id>
DMA Cache mc   <data_id>
```

- The decoder accepts only the opcode `DMA` (upper case).

### NoC
`send` / `recv`.
- **`send`**: `packet_id` tells the router which packet id to send; `data_id` tells the DMA which cache entry to send. All following ints are first taken as `dest_id`s; if the last token is `0`/`1` and there is at least one dest id before it, that token is read as the `truncate` flag (`1` = truncate the source cache entry after sending), not as a destination. **So a multicast list whose last core is 0 or 1 is misread**: `DMA NoC send 1900000 500000 3 2 1` sends only to cores 3 and 2, and truncates the source. Whenever you list two or more cores, always end with the flag (`… 3 2 1 0`). With more than one `dest_id`, `cast_type=MULTICAST`, otherwise `UNICAST`.
- **`recv`**: `packet_id` says which packet to take from the router; `data_id` is the cache id the received data gets as a new `Data_t`; all following ints are a list of segment sizes, which the decoder adds up to the total length.

### DRAM
`read` / `write`.
- `file_name`: the file to access, written as a **path relative to the repository root** with `/` separators (e.g. `new_code/DRAM_sim/DRAM_data/in_tensor/mlp/in_B1.bin`). Don't use absolute paths: they break as soon as the repository is somewhere else (for example `/workspace` in Docker), and `score_mlp.py` rejects them (see USER_GUIDE.md §12.4).
- Any word other than `read`/`write` (e.g. `reed`) and any index_mode other than `index`/`tensor` fail to decode (`DecodeError`).
- **index mode** (`index`): `row_start row_end col_start col_end`.
- **tensor mode** (mostly for K/V-cache access): `batch seq_start seq_end head_start head_end`, converted in the same way as for Array (see above).
- `data_id`: for `read`, the cache id the data read is stored under; for `write`, the cache id of the source data to write out.
- `data_reserved` (read only by `write`, bool 0/1): `1` truncates the source data in the cache after it has been written to DRAM.
- `pad <n>` (optional, for both read and write, at the end): pads the output to `n` columns per row (filled with 0). **The latency still counts only the size actually read** (`col_end - col_start`), not the padded size.

### Cache
- **`copy <src_data_id> <dst_data_id>`**: reads `cache[src_data_id]`, passes it through the pool and writes it back as `cache[dst_data_id]`. This is the only way to **rename a cache entry or create an alias** for it (sc_modules may not talk to each other through pointers, only by moving data through ports like this).
- **`mc <data_id>`**: the DMA sends a read request on cache port 6, and the result goes **directly to `MainCtrl.cache_data_in`** (it doesn't use the DMA's own cache_slot_); the instruction counts as done as soon as the request is sent. It was meant for cases where `MainCtrl` itself needs to read some cache data (rather than handing it to a compute unit). **In this project**: the only consumer of this path was the RPC subsystem, which has been deleted (it read `topk_idx`/the routing table, see [curr_arch.md §4.4](curr_arch.md)). `MainCtrl.cpp` no longer reads `cache_data_in` at all, and MLP instruction streams never issue this instruction. `DMADec` still accepts the syntax, but nothing uses the result: it is a leftover, dead path.

## TMU

```
TMU <mode> in <id_0> <reserved_0> [<id_1> <reserved_1> ...] out <out_id_0> [...] size <size_list>
```

`in`/`out` are literal tokens that separate the input list from the output list; the size fields come after `size`.
- The decoder accepts only the opcode `TMU` (upper case).

### mode
`concat`, `scatter`, `split`, `trans`, `view`, `pad`, `gather`.

### input list
A sequence of `(id, reserved)` pairs up to `"out"`: `<id_0> <reserved_0> <id_1> <reserved_1> ...` (`reserved` is 0/1).

### output list
A list of ids, up to the `"size"` keyword or the end of the line.

### size_list (depends on the mode)
| mode | size_list | Meaning |
|------|--------------|------|
| `view` | `<d0> <d1> ...` | The target shape (every token is a shape dimension) |
| `gather` | `<dim>` | The axis to gather along (a single integer); `num_parts` is always `0` |
| `concat`/`scatter`/`split`/`pad` | `<dim> <num_parts>` | `dim` = the axis to operate on, `num_parts` = the number of parts |
| `trans` | may be omitted | The whole `size` block may be omitted |

If the `size` keyword is missing (e.g. `trans` without it): `dim` defaults to `-1` and `num_parts` to `output_ids.size()`.

### gather mode
```
TMU gather in <src_id> <src_reserved> <idx_id> <idx_reserved> out <out_id> size <dim>
```
| Parameter | Meaning |
|------|------|
| `src_id` | Cache id of the source tensor (shape `[d0,...,N,...,dK]`, with N on axis `dim`) |
| `idx_id` | Cache id of the index tensor (a flat vector of integer indices stored as float, length K) |
| `out_id` | Cache id of the output tensor (same shape as src, but with size K on axis `dim`) |

### Examples
```
TMU concat   in 1 0 2 0   out 3          size 0 2
TMU scatter  in 4 0       out 5 6        size 0 2
TMU split    in 4 0       out 5 6 7      size 0 3
TMU trans    in 8 0       out 9
TMU view     in 10 0      out 11         size 4 16
TMU pad      in 12 0      out 13         size 1 4
TMU gather   in 10 0 11 0 out 12         size 0
```

## TCore (synchronization)

```
TCore WAIT
TCore LOCAL_SYNC
TCore GLOBAL_SYNC <barrier_id> <N> <core_id_0> <core_id_1> ... <core_id_{N-1}>
```

- The decoder accepts the opcode `TCore` or `TCORE`; the mode must be `WAIT`/`LOCAL_SYNC`/`GLOBAL_SYNC`.
- TCore instructions are **handled inline by `MainCtrl`** and are not dispatched to any unit's FIFO.

#### WAIT
No synchronization: `MainCtrl` simply advances the instruction pointer and keeps dispatching, with no extra cycles.

#### LOCAL_SYNC
Waits until all units of the current core (ArrayUnit/VectorUnit/DMA/TMU) report idle before going on to the next instruction. The implementation requires idle to be observed on **2 consecutive clock cycles**, to avoid a race while the busy flags propagate.

#### GLOBAL_SYNC
A distributed barrier. `MainCtrl` sends an arrive notice to the `GlobalSyncManager` and **stops dispatching** until every participant core of `barrier_id` has arrived; then the `GlobalSyncManager` sends a release to each participant and `MainCtrl` continues. Each core can have only one `GLOBAL_SYNC` in flight at a time (guaranteed by the blocked dispatch).

| Parameter | Type | Meaning |
|------|------|------|
| `barrier_id` | uint64_t | The unique id of this barrier; the same id must appear in the instruction streams of all participant cores, with the same participant list |
| `N` | int | The number of cores taking part in this barrier |
| `core_id_0..N-1` | int list | The ids of all cores that must arrive before the release |

Example (all 4 cores take part in barrier 42):
```
TCore GLOBAL_SYNC 42 4 0 1 2 3
```

## Note: sub-decoders not connected to the top-level decoder

The sub-decoders `Core/MainCtrl/Decoder/NoCDec/` and `Core/MainCtrl/Decoder/DRAMDec/` exist in the source, but `Decoder::decode()` never dispatches to them: NoC and DRAM accesses always go through the `DMA NoC ...` / `DMA DRAM ...` syntax above. Ignore those two sub-decoders' formats when you write instruction files.
